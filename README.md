# Stack user manual

Данный проект предназначен для работы со стеком, который защищен от повреждения данных и ведет подробный журнал своей работы.
```
- Стек с динамическим изменением размера (расширение и сжатие памяти).
- Защита данных: "канарейки" на структуре и на массиве, "яд" в неиспользуемых ячейках.
- Функция проверки стека, вызываемая перед каждой операцией.
- Запись всех действий в лог-файл с указанием файла и строки вызова.
- Коды ошибок с текстовой расшифровкой.
```

Проект создан в рамках образовательного семестрового курса МФТИ ФРКТ,
под руководством [Ильи Рудольфовича Дединского](https://ded32.net.ru/).

Проект создан на операционной системе MacOS. На иных платформах возможна некорректная работа.


## Установка и запуск:

1) Скачайте архив с проектом, распакуйте в произвольную директорию.
2) Если у вас не установлен компилятор языка С++ -- g++, установите его.
3) Скомпилируйте файл "main.cpp". Остальные файлы подключаются в него автоматически.
4) Запустите полученную программу.
5) В режиме отладки рядом с программой появится файл "STACK_LOG.log" с историей событий.
6) Готово!


## Описание функционала:

### Режимы работы:
-> main.cpp

- **Отладочный режим** включается строкой "#define _DEBUG" в начале main.cpp. Работают канарейки, яд, проверка стека и запись в лог. Ошибки сохраняются в переменную error.
- **Рабочий режим** включается, если эту строку убрать. Все проверки отключаются, остаются только assert. Программа работает быстрее.

Тип элементов стека (stack_elem) и способ печати элемента в лог (PRINT_ELEM_T) задаются в начале main.cpp, до подключения остальных файлов.

### Реализация функций стека:
-> stack.cpp, stack.h

- Функция **StackCtor** создает стек заданной вместимости. В режиме отладки выделяет память вместе с канарейками, заполняет ячейки ядом и проверяет стек.
- Функция **StackPush** добавляет элемент в конец стека. Если место закончилось, вызывает DomainExpansion и увеличивает память в 2 раза.
- Функция **StackPop** возвращает последний элемент и заменяет его ядом. Если элементов стало меньше половины вместимости, вызывает DomainExpansion и уменьшает память.
- Функция **DomainExpansion** меняет вместимость стека, переставляет правую канарейку в новый конец массива и заполняет свободные ячейки ядом.
- Функция **StackDestructor** заполняет массив ядом, освобождает память и обнуляет указатель на данные.

Все функции принимают дополнительные данные об ошибке и месте вызова (макрос DEBUG_INFO). В стеке не сжимается память, пока в нем не больше 8 элементов (MIN_CAP). Максимальный размер памяти ограничен константой MEM_LIM (500 KB).

### Реализация отладочных функций:
-> stack_debug.cpp, debug.h

- Функция **StackVerify** проверяет стек и пишет результат в лог: существует ли стек, не превышает ли размер вместимость, нет ли яда среди элементов, целы ли канарейки.
- Функция **PrintStack** печатает в лог содержимое стека: адрес данных, размер, вместимость, элементы и состояние канареек.
- Функция **CalcMemToCanary** считает размер памяти под массив вместе с двумя канарейками.
- Функция **PrintError** записывает в лог описание кода ошибки.

Для записи в лог используются макросы LOG, LOG_FUNC_INFO (начало функции), END_FUNC_LOG (успешное завершение) и CRUSH_FUNC_LOG (аварийное завершение).

### Коды ошибок:
-> debug.h

Возможные коды ошибок:
  1) **NO_MEMORY_TO_STACK** - не удалось расширить память.
  2) **SIZE_MORE_CAPACITY** - размер стека больше вместимости.
  3) **FIND_POISON** - среди элементов найден яд.
  4) **STACK_CALLOC_ERROR** - не удалось создать стек.
  5) **MEM_LIMIT_OR_LOWER_THAN_ZERO** - запрошено слишком много памяти.
  6) **CTOR_CRUSHED, PUSH_CRUSHED, POP_CRUSHED, DEST_CRUSHED** - проверка стека не пройдена в соответствующей функции.
  7) **GET_GOJO** - попытка взять элемент из пустого стека.

```
!!! Файл лога перезаписывается при каждом запуске программы.
Размер стека ограничен константой MEM_LIM в файле stack.h.
```
